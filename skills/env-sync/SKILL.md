# env-sync — 環境ファイルの双方向同期

ローカルの環境ファイルと、リポジトリで共有しているテンプレートを同期する。

## 基本方針

- 🔴 **ローカルの環境ファイルを変更する前に必ずユーザーへ確認する**（動いている環境を壊しうる）
- 🔴 **共有側への反映は必ず PR 経由。ベースブランチへ直接 push しない**
- 🔴 **個人設定値・秘匿値のマスキング / 復元を正確に行う**

## 設定

```bash
DEVKIT_ENV=$(bash .claude/devkit/config.sh) || exit 1
eval "$DEVKIT_ENV"
```

対応表（ローカルパス ↔ テンプレートパス）が設定に無ければ、**実物を確認してユーザーと合意してから進める。**

## マスキング規約

**ローカル → テンプレート（push）で、個人固有の値をプレースホルダへ戻す:**

| 対象 | ローカル値の例 | テンプレート値 |
|---|---|---|
| 個人ごとに払い出されるリソース名 | `...-<userid>-...` | `...-{name}-...` |
| 管理者メール等の個人アドレス | `me@example.com` | `admin@example.com` |

🔴 **置換対象のキーを限定する。** 「ユーザー ID の文字列を一律置換」にすると、**別のキーに偶然含まれる同じ文字列まで壊す**。対象キーを列挙して、そのキーの値だけ変換する。

🔴 **秘匿値（API キー・トークン・パスワード）は push しない。** テンプレート側はプレースホルダのままにする。実値の配布は別経路（シークレット管理）で行う。

## Phase 0: モードと事前確認

`pull`（テンプレート → ローカル）/ `push`（ローカル → テンプレート）/ `diff`（差分表示のみ）から選ぶ。

**個人設定値（ユーザー ID・メール）を先に取得しておく**（マスキング / 復元に使う）。

## Phase 1: 差分検出（全モード共通）

1. テンプレートの最新を取得する
2. **ローカルのマスキング済みコピー**を作業ディレクトリに作る（**ローカル本体は触らない**）
3. `diff` を取り、**キー単位で**差分を出す:
   - テンプレートにあってローカルに無い（**取り込むべき新規キー**）
   - ローカルにあってテンプレートに無い（**共有すべきか / 個人設定か**）
   - 値が違う（**個人設定の差分か、更新漏れか**）
4. 差分をユーザーに報告する

🔴 **「値が違う」を機械的に上書きしない。** 個人ごとに異なるべき値と、更新すべき値を分けて提示する。

## Phase 2-A: pull（テンプレート → ローカル）

1. 反映するキーを提示して確認を取る
2. **プレースホルダを個人設定値へ復元してから**ローカルへ書く
3. 反映後、ローカルの環境ファイルが読める形か確認する（構文・重複キー）

🔴 **ローカルの既存値を無条件に上書きしない。** 新規キーの追加を既定とし、既存値の変更は個別に確認する。

## Phase 2-B: push（ローカル → テンプレート）

1. 反映するキーを提示して確認を取る
2. 共有リポでブランチを切る
3. **差分のあるキーだけ**反映する（ファイル全体をコピーしない — 他人の変更を巻き戻す）
4. 🔴 **最終確認: マスキング漏れが無いか。** 個人アドレス・実キー・ユーザー ID が残っていないことを grep で確認する
5. コミット + PR 作成

## Phase 3: クリーンアップ

作業ディレクトリのコピーを削除する（**マスキング前のコピーを残さない**）。

## Notes

- 🔴 **必須の環境変数を追加する PR は、テンプレート側を先にマージして配布完了を確認してからアプリ側を出す。** 逆にするとアプリの CI が env 検証で落ちる
- **省略可能な環境変数（既定値を持つもの）はテンプレートに載らない構成もある。** 「テンプレートに無い = 未配布」と決めつける前に、アプリ側の env 定義で必須かどうかを確認する
- 🔴 **`sed -i ''` で環境ファイルを書き換えない。** サンドボックス下でエラーも出さず無反応になることがある。編集ツールを使う
