# local-init — ローカル環境の初回セットアップ

## 基本方針

- 🔴 **既存環境の破棄要否を最初に確認する。** 再構築・クリーン構築が目的なら**先に `/local-destroy`**。いきなり init を始めない
- 対話的な認証（ブラウザを開くログイン等）は**ユーザーに依頼する**（`! <command>` をプロンプトで実行してもらう）
- 各フェーズの結果を確認してから次へ進む。**まとめて流して最後に失敗を見つけない**

## Phase 0a: 既存環境の破棄確認

既にコンテナ・ボリュームがあるかを確認し、**あれば破棄するかをユーザーに聞く。**

## Phase 0b: 前提ツールとランタイム

```bash
DEVKIT_ENV=$(bash "$(git rev-parse --show-toplevel)/.claude/devkit/config.sh") || exit 1
eval "$DEVKIT_ENV"
```

- ランタイム管理ツールの設定ファイル（`.mise.toml` / `.tool-versions` 等）があれば、**それを SoT としてインストールする**
- 🔴 **複数のランタイム管理ツールを併用しない**（バージョンが食い違って原因不明の失敗になる）
- 必要なツール（コンテナランタイム・クラウド CLI 等）の導入状況を確認する

## Phase 0c: ユーザー情報の確認

個人ごとに払い出される値（ユーザー ID・個人用ストレージ名・管理者メール）を確認する。**環境ファイルのプレースホルダ置換に使う。**

## Phase 1: 環境ファイルの配置

1. 共有テンプレートから環境ファイルを取得する（`/env-sync` の pull 相当）
2. **プレースホルダを個人設定値へ置換する**
3. 配置結果を確認する（**必須キーが揃っているか**）

🔴 **`sed -i ''` で書き換えない**（サンドボックス下でエラーも出さず無反応になることがある）。編集ツールを使う。

## Phase 2: 認証情報

クラウド・パッケージレジストリの認証を設定する。**ブラウザ操作を伴うものはユーザーに依頼する。**

## Phase 3: 各リポジトリのセットアップ

`siblingRepos` を含む対象リポごとに依存をインストールする。**リポごとに成否を報告する。**

## Phase 4: DB 起動 → マイグレーション → 起動 → 初期データ

1. **DB を起動する**
2. **マイグレーションを適用する** — 🔴 **DB が起動していないと接続エラーになる。順序を飛ばさない**
3. ORM のクライアント生成が要るなら実行する
4. **サーバを起動する**
5. **初期データを投入する**（管理者アカウントの有効化・マスタデータ）
6. 動作確認後、必要なら環境を停止する

🔴 **単体のフロントだけ起動しても、依存するバックエンド・プロキシが無いと主要機能は流れない。** 一括起動タスクがあるならそれを使う。

## Phase 5: 完了メッセージと初回動作確認

```
ローカル環境の構築が完了しました
- 起動: <コマンド>
- URL: <ローカル URL>
- 停止: <コマンド> / 破棄: /local-destroy
```

初回動作確認をチェックリストで案内する:

1. トップページが開くか（**この時点ではアカウントが未有効でアクセスできないことがある**）
2. 初期データ投入でアカウントを有効化する
3. 再度トップページが開くか
4. 主要機能が 1 つ動くか

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| ポートが使用中 | `lsof -i:<port>` で特定。**強制終了は確認を取ってから** |
| ORM の生成エラー | 依存のインストール状態と、スキーマファイルのパスを確認 |
| DB 接続エラー | コンテナの起動完了を待つ（**healthcheck を待たずに叩くと必ず落ちる**）。接続先ホスト / ポートを確認 |
| 認証エラー | 対話ログインをユーザーに依頼する |
| 定期処理が動かない | **ローカルにはスケジューラが無いことがある。** 該当処理を手動で叩く（1 回の呼び出しで 1 件しか処理しない設計なら件数分ループする） |

## Notes

- 🔴 **`/local-init` の前に既存環境の破棄要否を必ず確認する**（Phase 0a）
- **完了 = 起動できた、ではない。** 初回動作確認まで通して初めて完了とする
