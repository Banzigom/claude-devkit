# db-backup — バックアップ取得

## 基本方針

- 🔴 **対象をユーザーに確認してから実行する**
- 🔴 **バックアップ ID の出力先を必ずユーザーに伝える。** 切り戻し（`/app-rollback`）で必須になる。**ここを伝え忘れると、取ったのに戻せない**

## 手順

### 0. 認証の確認

```bash
DEVKIT_ENV=$(bash "$(git rev-parse --show-toplevel)/.claude/devkit/config.sh") || exit 1
eval "$DEVKIT_ENV"
```

認証が切れている場合、**対話的なログインはユーザーに依頼する**（`! <command>` をプロンプトで実行してもらう）。

### 1. 対象の確認

全件 / 特定のプロジェクト・アカウント / 特定インスタンス のいずれか。

### 2. 実行

インフラ定義リポ（`infra.iacRepo`）にバックアップスクリプトがあればそれを使う。無ければクラウド CLI を直接使う。

**複数インスタンスをループするなら、1 件ごとに成否を記録する。** まとめて実行して最後の exit code だけ見ると、途中の失敗が埋もれる。

### 3. 結果確認

- 成功 / 失敗の件数と、失敗した対象の内訳
- 🔴 **バックアップ ID の出力ファイルパス**

### 4. 完了メッセージ

```
DB バックアップ完了
- 対象: <...>
- 成功 N / 失敗 M
- バックアップ ID: <出力ファイルパス>

切り戻しが必要な場合は /app-rollback にこのパスを渡す
```

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| 認証エラー | 対話ログインをユーザーに依頼する |
| 特定インスタンスだけ失敗 | インスタンスの状態を確認し、**進行中のオペレーションがあれば完了を待ってリトライ**する |
| 全件失敗 | 権限・プロジェクト指定を疑う。**リトライを繰り返さない** |
