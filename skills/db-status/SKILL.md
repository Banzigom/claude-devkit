# db-status — DB インスタンスの状態確認

対象 DB の状態・メトリクス・進行中オペレーションを確認する。**調査のみ。設定変更・再起動はしない。**

## 手順

### 1. 対象の確認

```bash
DEVKIT_ENV=$(bash .claude/devkit/config.sh) || exit 1
eval "$DEVKIT_ENV"
```

対象インスタンス（または全件）と目的（リリース後監視 / パフォーマンス調査 / バックアップ・リストアの進捗）をユーザーに確認する。**`infra.cloud` が未設定なら、どのマネージドサービスかを聞く。**

### 2. 基本情報

状態 / エンジンバージョン / インスタンスクラス / ディスクサイズを取る。

```bash
# 例（GCP Cloud SQL）
gcloud sql instances describe <instance> --project=<project> \
  --format="table(name, state, databaseVersion, settings.tier, settings.dataDiskSizeGb)"
```

### 3. オペレーション

- 直近のオペレーション一覧（バックアップ / リストア / メンテナンス）
- **進行中のオペレーション** — 実行中があるなら、後続の操作は**完了を待ってから**にする

### 4. メトリクス

接続数 / CPU / メモリ / ディスク使用率 / レプリケーション遅延。

🔴 **接続数を見るときは上限（インスタンスクラス由来 + アプリのプール設定）と一緒に見る。** 絶対数だけでは枯渇が近いか分からない。

### 5. 報告

現在の状態 / 異常の有無 / 進行中オペレーション / 推奨アクション。

## Notes

- 🔴 **同一インスタンスに複数環境が同居している構成では、tier 変更・再起動が全環境を同時に落とす。** 「本番の DB を触る」作業の周知範囲に開発・検証環境の利用者も含める。**環境ごとに別インスタンスだと決め打ちしない** — 構成を実際に確認する
- 単一ゾーン構成のインスタンスは、クラスを上げてもマネージドサービスの SLA 対象にならないことがある。**「上位クラス = 可用性が上がる」と短絡しない**
