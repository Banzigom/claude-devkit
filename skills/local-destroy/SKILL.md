# local-destroy — ローカル環境の破棄

## 基本方針

- 🔴 **破棄レベルをユーザーに確認してから実行する**
- 🔴 **データボリュームの削除は明示的に確認を取る**（不可逆）
- 🔴 **リポジトリ内のファイルを一切変更しない。** `git restore` / `git checkout` / `git stash` / ファイル編集はすべて禁止。**エラーが出てもファイルに手を加えず、状況を報告してユーザーの指示を仰ぐ**（他セッションの作業中変更を巻き込む事故になる）

## 手順

### 1. 破棄レベルの確認

| レベル | 内容 | 影響 |
|---|---|---|
| **コンテナのみ** | コンテナを落として削除 | **DB のデータは残る。** 次回の起動で復旧できる |
| **完全クリーン** | データボリュームも削除 | **マイグレーションと初期データ投入をやり直す必要がある。** DB が壊れたときのリセット用 |

### 2. 現在の状態確認

起動中のサービス・コンテナ・使用中ポートを確認して報告する。

### 3. 破棄の実行

プロジェクトに破棄タスク（`mise run destroy` / `make down` / `docker compose down` 等）があればそれを使う。無ければコンテナ定義から組み立てる。

### 4. 確認

**全ポートが解放され、対象コンテナが無いこと**を確認する。

### 5. 完了メッセージ

```
環境を破棄しました（<レベル>）
- 再起動: <起動コマンド>          ← コンテナのみの場合
- 再構築: /local-init             ← 完全クリーンの場合
```

## ポートが解放されない場合

```bash
lsof -i:<ポート番号>
```

**残っているプロセスを特定してユーザーに報告する。強制終了は確認を取ってから。**
