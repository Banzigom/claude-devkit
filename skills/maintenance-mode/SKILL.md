# maintenance-mode — メンテナンスモードの切替

インフラ定義（IaC）のフラグを切り替えて、メンテナンス画面の表示を制御する。

## 基本方針

- 🔴 **有効化か解除かをユーザーに確認してから実行する**
- 作業は `infra.iacRepo` のリポジトリで行う
- 🔴 **適用の完了まで見届ける**（PR マージ = 反映完了ではない）

## 手順

### 0. 前提確認

```bash
DEVKIT_ENV=$(bash "$(git rev-parse --show-toplevel)/.claude/devkit/config.sh") || exit 1
eval "$DEVKIT_ENV"
jq -r '.siblingRepos[]? | select(.name == "'"$DEVKIT_INFRA_IAC_REPO"'") | .path' "$DEVKIT_CONFIG"
```

IaC リポが無ければ報告して停止する。

### 1. 操作の確認

**有効化 / 解除** / **対象**（全体 or 一部）/ **理由**（コミットメッセージに使う）。

### 2. フラグの編集

設定の SoT（テナント設定ファイル等）で、対象のメンテナンスフラグを切り替える。

🔴 **設定の SoT を編集したら、生成物まで反映する。** テンプレートから環境ごとのファイルを生成する構成では、**SoT だけコミットすると生成物がドリフトしたまま PR がマージされ、対象に反映されない**（さらに次に別件で生成した人の PR に差分が混入する）。生成コマンドを実行し、`git status` で生成物にも変更が入っていることを確認する。

### 3. コミット・PR・適用

ブランチを切って PR を作る。**ベースブランチへ直接コミットしない。**

🔴 **適用の実体がどこかを確認する。** 「メインブランチへマージ = 適用」とは限らず、**デプロイ用ブランチへの反映が実体**という構成がある。マージ後に適用が始まったことを実際に確認する。

### 4. 反映確認

🔴 **設定が反映されても、稼働中のプロセスには届いていないことがある**（環境変数はプロセス起動時にしか注入されない）。反映には再起動が要る構成なら、それも含めて完了とする。

実際にメンテナンス画面が出る / 出なくなることを確認する。

### 5. 完了メッセージ

```
メンテナンスモードを <有効化 / 解除> しました
- 対象: <...>
- 適用: <確認方法と結果>
- 解除方法: /maintenance-mode で off を選択   ← 有効化した場合のみ
```

## 注意事項

- 適用には数分かかることがある。失敗したら適用ログを確認する
- **他の適用が進行中だとロック待ちになる。** 完了を待つ
- 🔴 **有効化したら「いつ誰が解除するか」を決めてから離れる**（解除忘れは障害と同じ影響になる）
